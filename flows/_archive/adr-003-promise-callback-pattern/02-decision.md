# ADR 003: Promise Callback Pattern - Decision

## Decision Statement

**Wrap all native module callbacks in Promises** using the `(successful, data)` tuple pattern for consistent async handling across the API.

## Rationale

1. **Modern JavaScript**: Promises and async/await are standard
2. **Error Handling**: Try/catch is cleaner than callback error checking
3. **Composability**: Promises can be combined with Promise.all(), Promise.race(), etc.
4. **Consistency**: All methods follow identical pattern
5. **Backward Compatible**: Could add callback support later if needed

## Compliance

All native module interactions MUST:
1. Return a Promise
2. Use `(successful, data)` callback pattern
3. Resolve with data on success
4. Reject with data on failure
5. Handle edge cases (like `data === true`)

## Error Handling Standards

1. **Enhance errors** with context (method name, parameters)
2. **Preserve error data** from native module
3. **Document error types** in specifications
4. **Consider wrapping** in Error objects for better stack traces

## Exceptions

None currently documented. All methods follow this pattern.

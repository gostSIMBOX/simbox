# ADR-002: Version Isolation Strategy

**Date**: 2026-03-04 (documented by /legacy analysis)
**Status**: Accepted
**Type**: Constraining

## Context

The project must support multiple PJSIP versions simultaneously:
- **PJSIP 2.7.1**: Legacy stable version (primary deployment)
- **PJSIP 2.9**: Newer version with improved audio APIs (Oboe, OpenSL ES)
- **PJSIP 2.10**: Latest version (external repository)

**Problem**: How to manage builds, patches, and artifacts for multiple PJSIP versions without conflicts?

## Decision

**Isolate each PJSIP version in separate directories with dedicated Docker images.**

### Implementation

1. **Separate build directories**:
   ```
   android_2.7.1/
   android_2.9/
   android_2.10/
   ```

2. **Separate patch directories**:
   ```
   src/patch_2.7.1/
   src/patch_2.9/
   src/patch_2.10/ (external)
   ```

3. **Separate Docker images**:
   ```
   react-native-sip2-builder/android_2.7.1
   react-native-sip2-builder/android_2.9
   react-native-sip2-builder/android_2.10
   ```

4. **Separate output artifacts**:
   ```
   dist/android_2.7.1/
   dist/android_2.9/
   dist/android_2.10/
   ```

5. **Dedicated build scripts**:
   ```
   build_android_2.7.1.sh
   build_android_2.9.sh
   build_android_2.10.sh
   ```

## Consequences

### Positive (+)

- **No version conflicts**: Each version completely isolated
- **Independent evolution**: Can update one version without affecting others
- **Clear separation**: Easy to understand which files belong to which version
- **Parallel builds**: Can build multiple versions simultaneously (different containers)
- **Version-specific patches**: Each version has tailored patches

### Negative (-)

- **Duplication**: Dockerfiles and build scripts duplicated across versions
- **Storage overhead**: Multiple Docker images with similar dependencies
- **Maintenance burden**: Changes must be applied to multiple versions
- **Inconsistency risk**: Versions may diverge unintentionally

### Trade-offs Accepted

1. **Duplication vs. shared base**: Chose duplication for clarity
   - Could use multi-build args or shared base images
   - Chose separate directories for explicit separation
   - Easier for developers to understand

2. **Storage vs. isolation**: Chose isolation
   - ~6-9GB total for all Docker images
   - Acceptable given modern storage capacities
   - Can optimize with shared base images later if needed

## Alternatives Considered

### Alternative 1: Single Docker image with version selection
- Use build arguments to select PJSIP version
- **Rejected** due to: complex dependency management, version conflicts, unclear separation

### Alternative 2: Shared base image with version-specific layers
- Common base with NDK/SDK, version-specific top layers
- **Rejected** due to: added complexity, marginal storage savings

### Alternative 3: External version management (git submodules)
- Use git submodules for each version
- **Rejected** due to: submodule complexity, not solving Docker isolation need

- Allows tracking upstream development
- Separate from internal patch management

## Architecture

### Release Scripts

#### 1. Main Release Script (`release.sh`)

**Purpose**: Full release process - build Android libraries and package into tarball

**Process**:
```bash
#!/bin/bash
set -e

rm -rf ./dist;           # Clean previous build artifacts
./build_android.sh;      # Build Android libraries (symlink to version-specific script?)
#./build_ios.sh;         # iOS build disabled

cd ./dist;
tar -czvf ../release.tar.gz ./   # Package everything into release.tar.gz
```

**Inputs**:
- `./build_android.sh` - Android build script (symlink or alias)

**Outputs**:
- `./release.tar.gz` - Complete release tarball

**Notes**:
- References `./build_android.sh` which doesn't exist as a file (may be symlink to `build_android_2.7.1.sh`)
- iOS build explicitly commented out

**Use Cases**:
- Re-release with same artifacts
- Testing release process without full build
- Manual artifact inspection before release

---

#### 3. Update Script (`update.sh`)

**Purpose**: Git auto-commit and push for release synchronization

**Process**:
```bash
#!/bin/bash
git add .
git pull
git commit -a -m "auto"
git push
```

**Behavior**:
1. Stage all changes
2. Pull latest from remote
3. Commit with generic "auto" message
4. Push to remote

**Notes**:
- Generic commit message "auto" lacks context
- No version tagging
- Simple sync workflow

## Known Issues

1. **build_android.sh reference**: Script references non-existent file
   - Likely intended as symlink to `build_android_2.7.1.sh`
   - May cause release.sh to fail

2. **No version in filename**: `release.tar.gz` is generic
   - Difficult to track multiple releases
   - Should include version: `release-2.7.1.tar.gz`

3. **Generic commit message**: "auto" provides no context
   - Should include version, timestamp, or changelog reference

4. **iOS disabled**: `#./build_ios.sh` commented out
   - iOS releases not supported

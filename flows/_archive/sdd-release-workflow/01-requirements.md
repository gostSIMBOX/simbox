# Release Workflow Requirements

> Spec-Driven Development: Packaging and distribution process for PJSIP libraries.

## Overview

Release workflow packages built Android PJSIP libraries into distributable tarballs for consumption by downstream projects.

## Stakeholders

- **Release managers**: Need reliable, repeatable release process
- **Developers**: Need consistent release artifacts
- **End users**: Need versioned, documented releases

## Goals

1. **Simple packaging**: Build → tar → distribute
2. **Two modes**: Full release (build+tar) and tar-only (re-package)
3. **External release repo**: Keep releases in separate repository
4. **Git integration**: Auto-commit and push releases

## Non-Goals

- iOS releases (currently disabled)
- Version management in filenames
- Complex release notes generation

## Constraints

- release.sh references `./build_android.sh` (may be symlink)
- release_onlytar.sh outputs to sibling directory
- Generic git commit messages

## Success Criteria

- [ ] release.sh produces release.tar.gz with all artifacts
- [ ] release_onlytar.sh can re-package without rebuild
- [ ] External release repo stays synchronized

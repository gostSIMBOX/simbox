# ADR 002: Dual Endpoint Strategy

> **Status**: DRAFT  
> **Type**: Enabling  
> **Generated by**: /legacy analysis

---

## Context

The react-native-tele module provides telephony functionality for React Native applications on Android. There are two different approaches to implementing Android telephony:

1. **PJSIP Library**: SIP-based VoIP telephony using pjsip-lib
2. **Android Telecom Framework**: Native Android telephony using `android.telecom` API

Both approaches have different use cases, capabilities, and requirements.

## Problem

The codebase contains two different Endpoint implementations:

1. **`src/Endpoint.js`**: Primary implementation, appears to use PJSIP (references PJSIP call states)
2. **`src/tele_endpoint.js`**: Alternative implementation using Android Telecom framework

Both implementations:
- Extend EventEmitter
- Subscribe to DeviceEventEmitter events
- Provide similar call control methods
- Bridge to native modules

**Questions**:
- Why do two implementations exist?
- Which one is primary?
- Should they be merged or kept separate?
- How should applications choose between them?

## Decision

**Chosen**: Maintain both implementations with clear documentation (status requires human confirmation)

Current evidence suggests:
- `Endpoint.js` is the primary, more complete implementation
- `tele_endpoint.js` is an alternative for Android Telecom integration
- They serve different use cases (SIP vs cellular)

### Implementation Differences

| Feature | Endpoint.js | tele_endpoint.js |
|---------|-------------|------------------|
| **Native Module** | TeleModule (PJSIP-based) | TeleModule (Android Telecom) |
| **Event Names** | `TeleCallReceived` (capital T) | `teleCallReceived` (lowercase t) |
| **Call States** | PJSIP_INV_STATE_* | Android STATE_* constants |
| **Methods** | 10+ call control methods | Basic methods only |
| **Features** | Hold, mute, speaker, decline | Basic answer/hangup |
| **Lines of Code** | 400+ | 200+ |
| **Documentation** | Full JSDoc comments | Minimal comments |

### State Mapping

**Endpoint.js (PJSIP states)**:
```javascript
PJSIP_INV_STATE_NULL        // Before INVITE sent/received
PJSIP_INV_STATE_CALLING     // After INVITE sent
PJSIP_INV_STATE_INCOMING    // After INVITE received
PJSIP_INV_STATE_EARLY       // After response with To tag
PJSIP_INV_STATE_CONNECTING  // After 2xx sent/received
PJSIP_INV_STATE_CONFIRMED   // After ACK sent/received
PJSIP_INV_STATE_DISCONNECTED // Session terminated
```

**tele_endpoint.js (Android states)**:
```javascript
STATE_CONNECTING = 9
STATE_RINGING = 2
STATE_DIALING = 1
STATE_ACTIVE = 4
STATE_DISCONNECTED = 7
STATE_DISCONNECTING = 10
```

State translation in tele_endpoint.js:
```javascript
if (data.extra1i === STATE_RINGING) {
    this.currentCall.state = 'PJSIP_INV_STATE_INCOMING';
}
if (data.extra1i === STATE_ACTIVE) {
    this.currentCall.state = 'PJSIP_INV_STATE_CONFIRMED';
}
```

## Consequences

### Positive

1. **Flexibility**: Applications can choose appropriate implementation
2. **SIP Support**: Endpoint.js supports SIP/VoIP calls
3. **Cellular Support**: tele_endpoint.js supports native cellular calls
4. **Gradual Migration**: Can migrate between implementations

### Negative

1. **Confusion**: Unclear which implementation to use
2. **Maintenance**: Two codebases to maintain and update
3. **Inconsistency**: Different event names, method signatures
4. **Code Duplication**: Similar logic duplicated in both files
5. **Export Confusion**: Both files export similar classes

### Neutral

1. **Same Event Pattern**: Both use EventEmitter + DeviceEventEmitter
2. **Shared Call Class**: Both use `src/Call.js` for call representation

## Implementation Details

### Endpoint.js Usage

```javascript
import { Endpoint } from './src';

const endpoint = new Endpoint();
await endpoint.start({ ReplaceDialer: false, Permissions: false });

endpoint.on('call_received', (call) => {
    console.log('Incoming call:', call.getRemoteNumber());
});

// Full API available
await endpoint.makeCall(1, 'sip:123@example.com', {}, {});
await endpoint.holdCall(call);
await endpoint.muteCall(call);
```

### tele_endpoint.js Usage

```javascript
import TeleEndpoint from './src/tele_endpoint';

const endpoint = new TeleEndpoint();
await endpoint.start({});

endpoint.on('call_received', (call) => {
    console.log('Incoming call');
});

// Limited API
await endpoint.answerCall(call);
await endpoint.hangupCall(call);
```

## Known Issues

1. **Event Name Inconsistency**: `TeleCallReceived` vs `teleCallReceived`
2. **Missing Methods**: tele_endpoint.js lacks hold, mute, speaker controls
3. **Commented Code**: tele_endpoint.js has extensive commented-out code blocks
4. **Import Path**: Both files import `Call` with different case (`./Call` vs `./call`)
5. **Unclear Exports**: `src/index.js` exports unclear which Endpoint

## Recommendations

### For Library Maintainers

1. **Clarify in README**: Document which implementation to use when
2. **Consider Renaming**: 
   - `Endpoint.js` → `PjsipEndpoint.js`
   - `tele_endpoint.js` → `AndroidTelecomEndpoint.js`
3. **Unify Event Names**: Use consistent event naming across both
4. **Feature Parity**: Either merge features or clearly document limitations
5. **Deprecation Plan**: If one should be deprecated, create migration path

### For Application Developers

1. **Use Endpoint.js** for SIP/VoIP applications
2. **Use tele_endpoint.js** for cellular-only applications
3. **Check event names** when subscribing to events
4. **Test both** to determine which fits your use case

## Alternatives

### Option 1: Single Unified Endpoint

Merge both implementations into one class with configuration:

```javascript
const endpoint = new Endpoint({
    mode: 'pjsip' | 'android-telecom' | 'auto'
});
```

**Pros**: Single API, less confusion  
**Cons**: Complex implementation, larger bundle size

### Option 2: Deprecate One

Choose one implementation and deprecate the other.

**Pros**: Clear direction, less maintenance  
**Cons**: Loss of functionality, breaking changes

### Option 3: Separate Packages

Split into two npm packages:
- `react-native-pjsip`
- `react-native-telecom`

**Pros**: Clear separation, independent versioning  
**Cons**: Package fragmentation, duplicate documentation

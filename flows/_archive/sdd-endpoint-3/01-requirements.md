## Overview

This document specifies the requirements for the Endpoint management module in react-native-tele, based on analysis of the existing implementation.

## Business Requirements

### BR-1: Telephony Module Initialization

The system SHALL provide a mechanism to initialize the telephony module before any operations can be performed.

**Rationale**: Native Android TeleModule must be started and validated before use.

### BR-2: Call Control

The system SHALL allow applications to control ongoing calls (answer, hangup, hold, mute, etc.).

**Rationale**: Core telephony functionality required for any calling application.

### BR-3: Event-Driven Architecture

The system SHALL notify applications of telephony events (incoming calls, state changes, termination).

**Rationale**: Calls are asynchronous; applications must react to external events.

## Functional Requirements

### FR-1: Module Start

| | |
|---|---|
| **ID** | FR-1 |
| **Title** | Module Initialization |
| **Priority** | HIGH |
| **Source** | Endpoint.start() |

**Description**:  
The system SHALL initialize the native telephony module when `start(configuration)` is called.

**Acceptance Criteria**:
1. Validates `NativeModules.TeleModule` exists
2. Throws descriptive error if native module is missing
3. Optionally sets app as default dialer (if `configuration.ReplaceDialer === true`)
4. Optionally requests permissions (if `configuration.Permissions === true`)
5. Returns Promise resolving to object with `accounts` and `calls` arrays
6. Rejects Promise with error data if initialization fails

**Dependencies**:
- NativeModules.TeleModule (Android native module)
- react-native-replace-dialer (optional, for ReplaceDialer feature)

### FR-2: Make Outgoing Call

| | |
|---|---|
| **ID** | FR-2 |
| **Title** | Make Outgoing Call |
| **Priority** | HIGH |
| **Source** | Endpoint.makeCall() |

**Description**:  
The system SHALL initiate an outgoing call to a specified destination.

**Acceptance Criteria**:
1. Accepts parameters: `sim`, `destination`, `callSettings`, `msgData`
2. Calls `NativeModules.TeleModule.makeCall()` with provided parameters
3. Returns Promise resolving to Call object on success
4. Rejects Promise with error data on failure
5. Handles edge case where native module returns `true` (creates Call with id:1)

**Input**:
- `sim`: Sim slot identifier
- `destination`: SIP URI or phone number
- `callSettings`: TeleCallSettings object
- `msgData`: TeleMsgData object

**Output**:
- Promise<Call> on success
- Promise rejection with error data on failure

### FR-9: Event Subscription

| | |
|---|---|
| **ID** | FR-9 |
| **Title** | Event Subscription |
| **Priority** | HIGH |
| **Source** | Endpoint constructor, DeviceEventEmitter |

**Description**:  
The system SHALL subscribe to native telephony events and re-emit them via EventEmitter.

**Acceptance Criteria**:
1. Constructor automatically subscribes to 6 DeviceEventEmitter events:
   - `TeleCallReceived`
   - `TeleCallChanged`
   - `TeleCallTerminated`
   - `TeleCallScreenLocked`
   - `TeleMessageReceived`
   - `TeleConnectivityChanged`
2. Each native event is transformed and emitted with appropriate data
3. Call events emit Call objects
4. Event listeners are NOT cleaned up (KNOWN ISSUE - memory leak risk)

**Emitted Events**:
- `call_received` - Incoming call notification
- `call_changed` - Call state update
- `call_terminated` - Call ended
- `call_screen_locked` - Screen lock state
- `message_received` - SIP message received
- `connectivity_changed` - Network connectivity change

### NFR-2: Asynchronous Operations

| | |
|---|---|
| **ID** | NFR-2 |
| **Title** | Promise-Based API |
| **Priority** | HIGH |

**Description**:  
All native module operations SHALL use Promises for async handling.

**Pattern**:
```javascript
return new Promise((resolve, reject) => {
    NativeModules.TeleModule.operation(params, (successful, data) => {
        if (successful) resolve(data);
        else reject(data);
    });
});
```

## Constraints

# Patch Management Requirements

> Spec-Driven Development: Version-specific patches for PJSIP libraries.

## Overview

Patch system for applying custom modifications to PJSIP source code, enabling Android-specific features, codec support, and audio device integration.

## Stakeholders

- **Developers**: Need to maintain custom PJSIP modifications
- **Build engineers**: Need reliable patch application during builds
- **End users**: Benefit from Android-specific optimizations

## Goals

1. **Version isolation**: Separate patches for each PJSIP version (2.7.1, 2.9, 2.10)
2. **Android integration**: JNI audio device support, OpenSL ES, Oboe
3. **Codec enablement**: G.729, G.7221 codec activation
4. **Audio optimization**: AEC (Acoustic Echo Cancellation), AGC, denoise
5. **Authentication improvements**: SIP auth header caching for Asterisk compatibility

## Non-Goals

- Upstream PJSIP patch submission
- Cross-version patch compatibility
- Runtime patch switching

## Constraints

- Patches must apply cleanly to specific PJSIP versions
- Patch application happens inside Docker container
- Patches are copied into build context before Docker build

## Success Criteria

- [ ] Patches apply without conflicts during build
- [ ] Android JNI audio device works correctly
- [ ] Codec support (G.729, G.7221) enabled
- [ ] AEC and audio enhancements functional

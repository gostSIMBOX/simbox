# ADR 001: EventEmitter Architecture - Decision

## Decision Statement

**Use both DeviceEventEmitter and EventEmitter** to provide a familiar, encapsulated event API while bridging native Android events to JavaScript.

## Rationale

1. **Developer Experience**: EventEmitter is more familiar to JavaScript developers than DeviceEventEmitter
2. **Encapsulation**: Native event names and data formats are hidden from applications
3. **Type Safety**: Events can be transformed into proper class instances (Call, Message)
4. **Flexibility**: Standard EventEmitter API supports multiple listeners, once, etc.

## Compliance

All event handling in react-native-tele MUST follow this pattern:

1. Extend EventEmitter in Endpoint class
2. Subscribe to DeviceEventEmitter in constructor
3. Transform and re-emit events with public names
4. Wrap event data in appropriate classes

## Exceptions

None currently documented.

# ADR-001: Docker-Based Build System

**Date**: 2026-03-04 (documented by /legacy analysis)
**Status**: Accepted
**Type**: Enabling

## Context

Building PJSIP with codec dependencies (OpenSSL, OpenH264, Opus, G.729) for Android requires:
- Specific Android NDK version (r12b)
- Specific Android SDK tools (r25.2.5)
- Multiple build tools (gcc, make, autoconf, etc.)
- Codec libraries built for each target architecture
- Consistent build environment across different developer machines

**Problem**: How to ensure reproducible builds across different host environments (Linux, macOS, Windows) while maintaining multiple PJSIP versions?

## Decision

**Use Docker containers for all PJSIP builds.**

### Implementation

1. **One image per PJSIP version**:
   - `react-native-sip2-builder/android_2.7.1`
   - `react-native-sip2-builder/android_2.9`
   - `react-native-sip2-builder/android_2.10`

2. **All dependencies bundled in image**:
   - Android NDK r12b
   - Android SDK tools r25.2.5
   - Build tools (gcc, g++, binutils, make, autoconf)
   - Codec sources (OpenSSL, OpenH264, Opus)
   - PJSIP source

3. **Build workflow**:
   ```
   docker build → docker run → docker cp → docker rm
   ```

4. **Multi-architecture support**:
   - Build for armeabi-v7a, x86, arm64-v8a, x86_64
   - Sequential builds via `TARGET_ARCHS` loop

## Consequences

### Positive (+)

- **Reproducibility**: Same build output regardless of host OS
- **Isolation**: No host system dependency conflicts
- **Version parallelism**: Multiple PJSIP versions can coexist
- **Simplified onboarding**: Developers only need Docker installed
- **Clean artifact extraction**: `docker cp` avoids volume permission issues
- **Self-documenting**: Dockerfile serves as build specification

### Negative (-)

- **Image size**: Large Docker images (~2-3GB each) with all dependencies bundled
- **Build time**: Downloading and building all dependencies in single layer
- **No multi-stage optimization**: Single-layer approach increases image size
- **Docker requirement**: Developers must have Docker installed and running
- **Sequential architectures**: Building architectures one-at-a-time is slower

### Trade-offs Accepted

1. **Single-layer vs. multi-stage**: Chose simplicity over optimization
   - All dependencies in one layer
   - Easier to debug and modify
   - Can optimize later if needed

2. **docker cp vs. volume mounts**: Chose cleaner separation
   - No host volume permission issues
   - Artifacts extracted after build completes
   - Slightly slower than volumes

3. **Sequential vs. parallel architectures**: Chose simplicity
   - Easier to debug build failures
   - Lower memory footprint
   - Can parallelize later if needed

## Notes

**Alternative considered**: Native builds on host system
- **Rejected** due to: host dependency conflicts, difficult multi-version support, platform-specific setup complexity

**Alternative considered**: Vagrant VMs
- **Rejected** due to: heavier resource usage, slower provisioning, Docker already sufficient

# ADR-002: Method Channel Communication

> Architectural Decision Record for Flutter-to-native communication.

## Status

DRAFT

## Type

Enabling

## Context

The Flutter SMS/USSD plugin needs to communicate with native platform code (Android Kotlin, iOS Swift/Obj-C) to access SMS functionality. Flutter provides MethodChannel for platform channel communication.

We need a communication mechanism that:
- Works across all Flutter-supported platforms
- Provides type-safe method calls
- Handles errors gracefully
- Follows Flutter conventions

## Decision

Use **MethodChannel** with the channel name `"flutter_smsussd"` for all platform communication.

### Architecture

```
┌─────────────────────┐
│   Flutter (Dart)    │
│                     │
│  MethodChannel      │
│  ("flutter_smsussd")│
└──────────┬──────────┘
           │ invokeMethod()
           ▼
┌─────────────────────┐
│   Native Code       │
│   - Android (Kotlin)│
│   - iOS (Swift)     │
│   - Web (JS)        │
└─────────────────────┘
```

### Method Channel Setup

**Dart Side**:
```dart
final methodChannel = const MethodChannel('flutter_smsussd');

@override
Future<bool> sendSms({
  required String phoneNumber,
  required String message,
}) async {
  final result = await methodChannel.invokeMethod<bool>('sendSms', {
    'phoneNumber': phoneNumber,
    'message': message,
  });
  return result ?? false;
}
```

**Android Side**:
```kotlin
channel = MethodChannel(flutterPluginBinding.binaryMessenger, "flutter_smsussd")
channel.setMethodCallHandler(this)

override fun onMethodCall(call: MethodCall, result: Result) {
  when (call.method) {
    "sendSms" -> sendSms(call.argument("phoneNumber")!!, ...)
  }
}
```

### Method Mapping

| Dart Method | Native Handler | Arguments | Returns |
|-------------|----------------|-----------|---------|
| `getPlatformVersion` | `getPlatformVersion` | None | String |
| `sendSms` | `sendSms` | phoneNumber, message | Boolean |

### Error Handling

**PlatformException Mapping**:
```dart
try {
  final result = await methodChannel.invokeMethod<bool>('sendSms', ...);
  return result ?? false;
} on PlatformException catch (e) {
  if (e.code == 'SMS_NOT_AVAILABLE') {
    throw UnsupportedError('SMS is not available on this device');
  } else if (e.code == 'NO_VIEW_CONTROLLER') {
    throw StateError('No view controller available');
  } else if (e.code == 'SMS_SEND_ERROR') {
    throw StateError('Failed to send SMS: ${e.message}');
  }
  rethrow;
}
```

**Error Codes**:
- `SMS_NOT_AVAILABLE` → UnsupportedError
- `NO_VIEW_CONTROLLER` → StateError (iOS)
- `SMS_SEND_ERROR` → StateError
- `NOT_SUPPORTED` → UnsupportedError
- `PERMISSION_DENIED` → Returned as false
- `INVALID_ARGUMENTS` → Returned as error
- `NO_ACTIVITY` → Returned as error

## Consequences

### Benefits

✅ **Standard Mechanism**: Uses Flutter's recommended approach
✅ **Type Safety**: Strong typing for arguments and return values
✅ **Error Handling**: PlatformException provides structured errors
✅ **Cross-Platform**: Same channel name works across all platforms
✅ **Testability**: Method channel can be mocked in tests
✅ **Single Channel**: All methods use one channel (simpler)

### Trade-offs

⚠️ **Serialization Overhead**: Arguments serialized/deserialized (minimal for small data)
⚠️ **Async Only**: All method channel calls are asynchronous
⚠️ **String-based Method Names**: Typos in method names cause runtime errors

### Limitations

⚠️ **Platform Disparities**: Different platforms may support different methods
⚠️ **Error Code Consistency**: Must maintain consistent error codes across platforms

## Compliance

- Channel name MUST be `"flutter_smsussd"` across all platforms
- All method calls MUST use `invokeMethod<T>()` with explicit type
- Arguments MUST be passed as Map<String, dynamic>
- Error codes MUST be consistent across platforms
- All exceptions MUST be caught and mapped to Dart-friendly errors

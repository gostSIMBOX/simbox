# Requirements: Method Channel Module

> Flutter-to-native communication layer for SMS/USSD plugin.

## Overview

This module implements the method channel communication between Flutter and native platforms. It serves as the default platform implementation, handling all native interop through Flutter's MethodChannel mechanism.

## Functional Requirements

### FR-1: Method Channel Communication

**Description**: Provide bidirectional communication between Flutter and native code.

**Acceptance Criteria**:
- [ ] Method channel named `"flutter_smsussd"` established
- [ ] All platform interface methods invoke corresponding native methods
- [ ] Arguments passed as type-safe maps
- [ ] Return values properly deserialized

### FR-2: Method Implementations

**Description**: Implement all 6 platform methods with proper method channel calls.

**Acceptance Criteria**:
- [ ] `getPlatformVersion()` invokes `"getPlatformVersion"` method
- [ ] `sendSms()` invokes `"sendSms"` with phoneNumber and message arguments
- [ ] `getSmsMessages()` invokes `"getSmsMessages"` and returns list
- [ ] `getSmsMessagesByPhoneNumber()` invokes `"getSmsMessagesByPhoneNumber"` with filter
- [ ] `requestSmsPermissions()` invokes `"requestSmsPermissions"`
- [ ] `hasSmsPermissions()` invokes `"hasSmsPermissions"`

### FR-3: Exception Handling

**Description**: Translate platform exceptions to Dart-friendly errors.

**Acceptance Criteria**:
- [ ] `SMS_NOT_AVAILABLE` → `UnsupportedError`
- [ ] `NO_VIEW_CONTROLLER` → `StateError`
- [ ] `SMS_SEND_ERROR` → `StateError`
- [ ] `NOT_SUPPORTED` → `UnsupportedError`
- [ ] Other PlatformExceptions rethrown unchanged

### FR-4: Type Safety

**Description**: Maintain strong typing throughout method channel communication.

**Acceptance Criteria**:
- [ ] All method parameters are typed (no `dynamic`)
- [ ] Return types are explicit
- [ ] Required parameters use `required` keyword
- [ ] List deserialization uses proper casting

### FR-5: Testability

**Description**: Enable unit testing of method channel calls.

**Acceptance Criteria**:
- [ ] Method channel marked `@visibleForTesting`
- [ ] Channel can be mocked in tests
- [ ] No hidden dependencies or side effects

## Non-Functional Requirements

### NFR-1: Performance

**Description**: Minimal overhead from method channel abstraction.

**Metrics**:
- Method channel calls complete in <10ms
- No unnecessary serialization/deserialization
- Argument maps are lightweight

### NFR-2: Reliability

**Description**: Robust error handling for platform communication failures.

**Metrics**:
- All platform exceptions caught and handled
- No unhandled exceptions propagate to caller
- Error messages preserve original platform error details

### NFR-3: Maintainability

**Description**: Clear, understandable code structure.

**Metrics**:
- Each method implementation is self-contained
- Exception handling is consistent across methods
- Code follows Flutter plugin conventions

### NFR-4: Compatibility

**Description**: Support all target platforms.

**Metrics**:
- Android: Full implementation
- iOS: Limited implementation (composer only)
- Web: Stub implementation
- Linux/macOS/Windows: Registered but not implemented

## Dependencies

## Constraints

### Technical Constraints
- Must use Flutter's MethodChannel API
- Must extend FlutterSmsussdPlatform abstract class
- Must handle PlatformException from native calls

### Platform Constraints
- iOS cannot read SMS messages (returns NOT_SUPPORTED)
- Web cannot send/read SMS (stub only)
- Desktop platforms not implemented

# ADR-003: iOS Limitations (Composer Only)

> Architectural Decision Record for iOS SMS functionality limitations.

## Status

DRAFT

## Type

Constraining

## Context

iOS has strict security policies that limit app capabilities. Unlike Android, iOS does not provide APIs for:
- Sending SMS programmatically
- Reading SMS messages from the device
- Accessing SMS database

The plugin must work within these iOS limitations while maintaining a consistent API across platforms.

## Decision

**iOS Implementation**: Use MessageUI framework to open native SMS composer only.

### What iOS CAN Do

✅ Open native Messages app with pre-filled content
✅ Pre-fill recipient phone number
✅ Pre-fill message body
✅ Let user manually send the message

### What iOS CANNOT Do

❌ Send SMS programmatically without user interaction
❌ Read SMS messages from device
❌ Access SMS database
❌ Check SMS permission status (not needed)
❌ Request SMS permissions (not needed)

### Implementation Approach

**iOS Code** (Swift/Obj-C):
```swift
import MessageUI

// Opens native SMS composer
func sendSms(phoneNumber: String, message: String) {
  if MFMessageComposeViewController.canSendText() {
    let controller = MFMessageComposeViewController()
    controller.body = message
    controller.recipients = [phoneNumber]
    controller.messageComposeDelegate = self
    // Present modally - user must tap Send
  }
}
```

**Dart Side Behavior**:
```dart
// On iOS: Opens composer, returns false if user cancels
bool success = await plugin.sendSms(
  phoneNumber: '+1234567890',
  message: 'Hello from Flutter!',
);
// Note: success = true only if user actually sends
```

### API Consistency

The plugin maintains the same API across platforms, but behavior differs:

| Method | Android | iOS | Web |
|--------|---------|-----|-----|
| `sendSms()` | ✅ Sends directly | ⚠️ Opens composer | ❌ Not supported |
| `getSmsMessages()` | ✅ Returns all | ❌ Throws NOT_SUPPORTED | ❌ Throws NOT_SUPPORTED |
| `getSmsMessagesByPhoneNumber()` | ✅ Returns filtered | ❌ Throws NOT_SUPPORTED | ❌ Throws NOT_SUPPORTED |
| `requestSmsPermissions()` | ✅ Requests runtime | ⚠️ Returns true (not needed) | ❌ Not applicable |
| `hasSmsPermissions()` | ✅ Checks permissions | ⚠️ Returns true (not needed) | ❌ Not applicable |

### Error Handling

**iOS-specific errors**:
- `NO_VIEW_CONTROLLER`: No activity available to present composer
- `NOT_SUPPORTED`: For read operations (getSmsMessages, etc.)

**Dart-side Exception**:
```dart
try {
  await plugin.getSmsMessages();
} on UnsupportedError catch (e) {
  // iOS: "Reading SMS messages is not supported on this platform"
}
```

## Consequences

### Benefits

✅ **Honest Limitations**: Clearly documents what iOS can/cannot do
✅ **Graceful Degradation**: App doesn't crash, throws appropriate errors
✅ **User Control**: User explicitly approves each message on iOS
✅ **Security**: No workarounds that might violate App Store guidelines

### Trade-offs

⚠️ **Inconsistent UX**: iOS users have different experience than Android
⚠️ **Manual Send**: iOS users must tap "Send" button manually
⚠️ **No Read Support**: iOS apps cannot read SMS messages at all

### Limitations

⚠️ **Cannot Bypass**: No technical workaround for iOS limitations
⚠️ **App Store Review**: Must comply with MessageUI usage guidelines
⚠️ **User Confusion**: Users may expect same behavior as Android

## Mitigation Strategies

### For Developers

1. **Platform Detection**: Check platform and adjust UX accordingly
   ```dart
   if (Platform.isIOS) {
     // Show message: "You'll need to tap Send in the Messages app"
   }
   ```

2. **Error Handling**: Handle NOT_SUPPORTED errors gracefully
   ```dart
   try {
     await plugin.getSmsMessages();
   } on UnsupportedError {
     // Show: "SMS reading not available on iOS"
   }
   ```

3. **Documentation**: Clearly document iOS limitations in README

### For Users

1. **Clear Messaging**: Explain iOS behavior before opening composer
2. **Fallback Options**: Provide alternative communication methods
3. **Platform-specific Features**: Hide iOS-incompatible features

## Compliance

- iOS implementation MUST use MessageUI framework
- iOS MUST NOT attempt to bypass SMS restrictions
- Error codes MUST be consistent: NOT_SUPPORTED for read operations
- Documentation MUST clearly state iOS limitations

## Business Requirements

### BR-1: SIM-Bank Registry

The system SHALL maintain a registry of all SIM-bank devices.

**Rationale**: Operators need to track deployed devices, their configuration, and status.

**Entities**: SimBank (device metadata), SimSlot (per-slot state)

### BR-2: SIM Slot State Tracking

The system SHALL track the state of each SIM slot including IMSI, ICCID, operator, and signal strength.

**Rationale**: Operators need visibility into individual SIM card status for operations and troubleshooting.

**Source**: `SimSlot` model with IMSI, ICCID, Operator, Status, Power, Signal fields.

### BR-3: Task Scheduling

The system SHALL support scheduled tasks with cron-based scheduling.

**Rationale**: Automated operations (sync, maintenance, power cycles) need to run on schedule.

**Source**: `SchedulerTask` model with cron Schedule field.

### BR-4: Event Audit Trail

The system SHALL maintain an audit trail of all system events.

**Rationale**: Operations team needs historical data for troubleshooting and compliance.

**Source**: `SystemEvent` model with Type, Source, Message, Level fields.

### BR-5: Soft Delete Support

The system SHALL support soft deletion for all entities.

**Rationale**: Deleted records must be recoverable and auditable.

**Source**: `gorm.DeletedAt` field on all models.

## Technical Requirements

### TR-1: Connection Pooling

The system SHALL use database connection pooling.

**Rationale**: Efficient resource utilization under concurrent load.

**Source**: `MaxIdleConns=5`, `MaxOpenConns=configurable`, `ConnMaxLifetime=1hr`

### TR-2: Automatic Migration

The system SHALL automatically migrate database schema on startup.

**Rationale**: Simplify deployment and version management.

**Source**: `AutoMigrate(SimBank, SimSlot, SchedulerTask, SystemEvent)`

### TR-3: Global Database Access

The system SHALL provide global database instance access.

**Rationale**: Simplify data access from any component.

**Source**: Package-level `var DB *gorm.DB`

### TR-4: Singular Table Names

The system SHALL use singular table names.

**Rationale**: Consistency and clarity in naming convention.

**Source**: `schema.NamingStrategy{SingularTable: true}`

### TR-5: Automatic Timestamps

The system SHALL automatically track creation and update timestamps.

**Rationale**: Audit trail and debugging.

**Source**: GORM's `CreatedAt`, `UpdatedAt` fields.

## Non-Functional Requirements

### NFR-1: Connection Limits

Default connection pool SHALL be:
- MaxIdleConns: 5
- MaxOpenConns: 10 (configurable)
- ConnMaxLifetime: 1 hour

### NFR-2: Query Performance

IMSI field SHALL be indexed for fast lookups.

**Rationale**: Frequent queries by IMSI.

### NFR-3: Data Integrity

All entities SHALL have proper foreign key relationships.

**Rationale**: Referential integrity.

### NFR-4: Graceful Shutdown

Database connections SHALL be properly closed on shutdown.

**Rationale**: Prevent resource leaks.
